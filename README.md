# 工银数界 DataFence

面向大型商业银行数据安全场景的私有部署验证系统，支持 Windows 本机与内网 HTTPS。通过真实账号、合成银行数据、受控查询/导出和可追溯实验，验证访问目的核验、行为异常、攻击链关联与执行前阻断。

**业务沙盒和受控交付使用合成银行数据；公开 UCI 数据独立记录来源。未接入工商银行或任何真实银行系统。**

当前版本按角色分成业务与安全两个空间。绑定员工的业务账号按工单查询/导出合成客户数据并查看个人操作；安全分析员在统一事件队列核对业务依据、实际交付和阻断结果，保存人工研判。管理员可管理账号并切换两空间。原有演练与模型评测保留在安全侧。完整安装和内网配置见 [Windows 部署说明](DEPLOYMENT_WINDOWS.md)，双工作台操作见 [功能手册](PRODUCT_GUIDE.md)。

已建立[多角色评审与整改流程](PROFESSIONAL_REVIEW.md)。16条带来源和版本的项目知识、六模块分析工作台、持久研判及完整演示仍可使用。新旧评审原始失败、验证和发布包均保留；最新验收结论见评审文档。

## 本机运行（Windows）

### 从 GitHub 获取源码

```powershell
git clone https://github.com/xqz84/DataFence.git
cd DataFence
.\scripts\setup.ps1
.\.venv\Scripts\python.exe -m datafence.training --name iforest-v2 --promote
.\scripts\start-private.ps1
```

以上命令用于首次安装，需要 Python 3.12+、Node.js 和 npm。本地训练会生成并校验合成正常行为模型，门槛通过后私有启动器才加载 `iforest-v2`。训练版本名不能覆盖已有目录；已安装且已有该模型时不重复训练，直接启动。运行时再生成合成银行与本机账号数据。

GitHub 仓库提交源码、依赖锁定文件、测试与说明文档；本机商汤密钥、账号/会话、数据库、备份、实验原始输出、公开数据下载和依赖目录留在本地。新电脑需要自己设置管理员，并按需要重新配置商汤凭据；源码下载不附带此前本机账号或模型训练产物。项目整体背景与算法详解见 [GPT 项目总说明](GPT_PROJECT_BRIEF.md)。

### 在现有本机工作区运行

需要 Python 3.12+、Node.js 和 npm。首次安装：

```powershell
cd E:\gonghang
.\scripts\setup.ps1
.\scripts\start.ps1
```

打开 [DataFence 本机控制台](http://127.0.0.1:8765)。首次在本机页面设置管理员，无默认密码。首次启动生成合成实体并写入 `runtime/datafence.sqlite3`，后续启动复用数据。默认仅本机访问；内网模式必须显式配置登录、HTTPS和允许的Host/Origin。

如果本机 PowerShell 策略不允许直接运行脚本，也可以逐条执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt -e .
cd frontend
npm.cmd ci
npm.cmd run build
cd ..
.\.venv\Scripts\python.exe -m datafence.server --port 8765
```

开发前端可在第二个终端进入 frontend 执行 `npm.cmd run dev`，访问 http://127.0.0.1:5173；API 代理到8765。构建版本通过 FastAPI 同源服务，不需额外前端服务。

## 日常主线与可选演练

业务人员登录后直接选择自己绑定员工的工单、地区和申请数量，执行查询或导出，核对返回量、工单额度与操作记录。安全人员打开首页或“风险事件”，默认看到需关注的待研判队列；选择记录即可核对业务理由、来源、实际交付与证据并保存结论。保存后页面转到对应状态且保留该记录。两端操作的详细口径见 [功能手册](PRODUCT_GUIDE.md)。

需要验证防护场景时，可进入“攻击模拟实验室”的完整演示向导：一次启动正常查询、已审批批量交付和异常访问三个真实沙盒运行，再查看事件证据、相关知识、人工研判并确认完成。演示编号保存于服务器，页面链接可刷新恢复；服务中断明确标记中断，不补跑未执行行为。向导只使用本地规则与行为模型，不调用商汤；模型实测在独立场景与评测页查看。

需要手动改变规模或观察商汤语义时，可按下列路径逐步运行单场景：

1. 打开安全态势，查看合成银行规模和当前真实运行记录。
2. 在攻击模拟实验室运行“正常业务对照”，确认普通访问完成。
3. 运行“已审批批量业务对照”，查看其数据沿查询、导出、压缩到合作方模拟接收端，存在真实本地回执。
4. 选择“组合型数据泄漏”、员工 E0038、18000条记录并启动。
5. 实时监控展示实际风险、证据和控制动作。若导出阶段已被阻断，其依赖的后续步骤显示未执行；不为走完剧本强行放行。
6. 查看员工行为、访问意图和风险事件详情，核对同一个事件的工单、范围和对象来源。
7. 审计与取证执行事件链/回执校验；评测与报告启动独立离线评测并查看原始产物路径。

攻击场景中的外传始终为本地模拟账本写入。用户显式配置商汤后，只有裁剪后的合成安全上下文会发往官方推理接口，不发送客户原始行、密钥或评测标签。NOTIFY_SOC 是本地模拟通知记录，不向任何人发送消息。

## 已实现的主线

- 合成银行：100员工、50000客户、80000账户、200000交易、6250贷款、200工单。
- 六类异常场景及两个正常对照；可配置员工、规模、导出、压缩、上传和速度。
- 规则、实际训练的 Isolation Forest、工单目的核验、五维风险、会话/对象关联。
- 执行前策略控制、实际合成记录集合流转、模拟接收回执、冻结后停止、事件与回执摘要校验。
- 七个核心页面、SQLite持久化、本机请求保护、幂等、重启恢复及独立评测。
- 本地行为模型的独立训练、校准、留出、晋升与 JSON 安全加载；本机已选择 iforest-v2。
- 商汤执行前涉敏 AI 语义审查、只读附加解释、加密凭据、持久调用预算、输出校验与故障暂缓；保留可选 Ollama。
- 工单额度的事务预留/确认/撤回、会话或显式全生命周期范围、重启持久化。额度按获准 QUERY/API 请求记录数计量。

运行指标与页面计数均来自本机产物，初始状态不填充虚构准确率。具体检查记录见 `VALIDATION.md`。

## 当前限制

- 商汤 API 集成不是训练其模型权重。真实开发诊断与本地行为模型训练分别记录；少量合成样例不能证明银行泛化。
- AI_PROMPT 目前是受控请求入口，没有下游生成业务答案的模型或真实输出外传；不能把请求暂缓率描述成 AI 输出泄漏阻断率。
- Ground Truth 在数据结构和模块层面隔离，同一操作系统账号仍可读取标签文件；尚无操作系统强制权限隔离。
- 固定模板得到的高指标只能说明模板内表现，不代表真实银行泛化。挑战集是开发诊断，不能当独立留出测试反复使用。
- 2026-10-03 已用显式合成攻击标签训练离线监督候选，但其异构开发挑战核心攻击 0/30 检出，故未晋升。现行 `iforest-v2` 仍只学习合成正常行为；两者都不是银行真实攻击训练或生产准入证据。见 `ATTACK_TRAINING_20261003.md`。
- 当前为单组织、单进程私有服务，已有平台账号和角色；没有银行统一身份连接器、多租户或外部可信审计。额度确认与事件审计不是跨库原子事务；异常窗口采取保守占用，需人工核查。
- 日志导入是事后观察；真实交付门控仅覆盖接入本系统受控查询/导出的合成资产，不会自动拦截其他数据库、终端或外部系统。公开业务数据无攻击标签，CERT r1也无对应官方攻击主标签，不能据此声称已验证现实攻击召回率。

## 商汤与本地模型训练

当前本机通过用户提供的密钥配置了商汤 `sensenova-6.8-flash-lite`，实际调用状态和本地预算显示在“AI安全智能体”“系统管理”及事件详情中。`configured` 不代表每次调用成功。

凭据以 Windows 当前用户 DPAPI 加密保存在忽略提交的 `runtime/secrets/`，配置在 `runtime/llm.json`；项目配置优先于同名环境默认模型与密钥。其他电脑需重新配置，不能复制密文当作通用密钥：

```powershell
.\.venv\Scripts\python.exe scripts\configure_sensenova.py
```

默认本地预算为每日 UTC 100 次请求、200000 token，当前最大输出2400 token、temperature=0.2；预算按真实返回计量，超时未知消耗保守预留。这不是供应商账户余额或金额保证。系统不自动重试；连续失败短暂熔断，涉敏 AI 审查失败时暂缓该请求而不认定恶意。高风险事后解释最多每次演练两次。

已保留三轮各24次的真实商汤调用。前两轮使用1800输出上限与默认采样，有效返回分别为19/24、20/24；第三轮验证当前2400/0.2及网络硬化配置，24/24有效、13条违规拒绝、11条正常放行，核验耗时p95为15.128秒。三轮复用同24个已公开的开发样例，最后一轮全部命中只说明这套回归通过，不能外推为真实银行准确率或稳定性保证。全部失败、参数、源码快照及可重算结果见 `SENSENOVA_REPORT.md`。

行为模型已经完成训练；重新训练可指定一个未使用的版本名，只有门槛全部通过才晋升：

```powershell
.\.venv\Scripts\python.exe -m datafence.training --name my-behavior-v2 --promote
```

训练产物位于 `runtime/models/`，重启服务加载当前晋升版本。该目录不随源码提交；全新安装若没有产物会明确使用旧版基线。详见 `TRAINING_REPORT.md`，额度口径与独立演示见 `QUOTA_LEDGER.md`，商汤真实测试见 `SENSENOVA_REPORT.md`。

## 可选本地模型

已有本地 Ollama 和已安装模型时，可在启动 DataFence 的同一终端设置 `$env:DATAFENCE_LLM_PROVIDER='ollama'`、`$env:DATAFENCE_LLM_MODEL='你的本地模型名'` 后重新启动服务。此模式只访问固定 `127.0.0.1:11434/api/chat`；不自动下载模型、不接受任意推理地址、不需要云密钥。`.env.example` 仅提供配置示例，程序不会自动读取 `.env`。

Ollama 守护进程还需自行配置 `OLLAMA_NO_CLOUD=1`，避免其代理云模型；回环 HTTP 地址本身不能证明独立守护进程不联网。[Ollama 官方说明](https://docs.ollama.com/faq)。本轮未安装 Ollama 或下载模型。

Ollama 模式只为已达到高风险阈值的事件提供附加解释，不能改变分数或执行动作；低风险预筛漏检不会被这个本地适配器自动纠正。商汤模式另有执行前语义门。原始离线评测与 challenge-v1 的指标均不包含云语义效果。
